# 지사 영역 폴리곤 + 라벨 — 설계

날짜: 2026-08-19

## 목적

지도에 회사 지사 5곳의 위치를 건물 크기의 사각형과 이름 라벨로 표시한다. 맛집 마커와 달리
이건 고정된 배경 정보다 — 검색 결과도 사용자 데이터도 아니고, 항상 같은 자리에 있다.

## 좌표

카카오 주소 검색 API(`/v2/local/search/address.json`)로 한 번 조회해 얻은 값을 상수로 박는다.
지사 주소는 바뀌는 값이 아니라서 런타임에 매번 조회할 이유가 없고, 그러면 일일 쿼터만 쓴다.

| 지사 | lat | lng | 원 주소 |
|---|---|---|---|
| 서울지사 | 37.4990536 | 127.0323059 | 서울시 강남구 역삼동 823-21, 대공빌딩 4층 2호 |
| 광주지사 | 35.1545550 | 126.8494740 | 광주광역시 서구 상무중앙로78번길 5-6, 영효빌딩 9층 820호 |
| 대전지사 | 36.3594186 | 127.3789057 | 대전광역시 서구 청사로 136, 대전무역회관 12층 R1227호 |
| 부산지사 | 35.1720592 | 129.1284326 | 부산광역시 해운대구 센텀서로 30, KNN빌딩 22층 |
| 대구지사 | 35.8343778 | 128.6807340 | 대구광역시 수성구 알파시티1로31길 26, 아트브릿지스 3층 |

층·호수는 2D 지도에 표현할 수 없으므로 데이터에 담지 않는다.

참고: 서울지사 좌표는 `useGeolocation.ts`의 폴백 좌표와 사실상 같은 지점이다 — 그 주석의
"대공빌딩"이 곧 서울지사다. 우연이 아니므로 어느 한쪽을 고칠 때 다른 쪽을 같이 본다.

## 사각형 근사

카카오에는 건물 외곽선 API가 없다. 주소 조회는 점 하나만 준다. 그래서 각 지사를
**중심점 + 폭 + 길이 + 회전각**으로 기술하고, 그 다섯 숫자로 사각형 네 꼭짓점을 계산한다.

기본값은 40m × 30m × 0°로 두고, 지도 위성뷰를 보면서 지사별로 숫자만 고쳐 맞춘다.
회전각이 필요한 이유는 건물이 정북 정렬인 경우가 드물어서, 축 정렬 사각형을 얹으면
실제 건물에 대각선으로 삐뚤게 앉기 때문이다.

**이 값들은 눈으로 맞추는 보정값이다.** 처음부터 정확할 수 없고, 정확해질 필요도 없다 —
지사가 어느 건물에 있는지 알아보게 하는 것이 목적이다.

## 파일

| 파일 | 책임 |
|---|---|
| `components/branchOffices.ts` (신규) | 지사 5곳의 상수 테이블 + `rectangleCorners()` 순수 함수 |
| `components/branchOffices.test.ts` (신규) | `rectangleCorners()`의 vitest |
| `components/MapView.tsx` | 폴리곤과 라벨 오버레이를 그리는 effect 하나 |
| `app/globals.css` | 라벨 스타일 |

### `branchOffices.ts`

```ts
export interface BranchOffice {
  name: string;        // "서울지사"
  lat: number;
  lng: number;
  widthM: number;      // 동서 방향 폭(회전 전), 미터
  heightM: number;     // 남북 방향 길이(회전 전), 미터
  rotationDeg: number; // 시계방향 회전, 0이면 정북 정렬
}

export function rectangleCorners(office: BranchOffice): { lat: number; lng: number }[];
```

`rectangleCorners`는 중심 기준 네 모서리를 미터 단위로 잡고, 회전 행렬을 적용한 뒤,
미터를 위경도 차이로 환산해 절대 좌표 4개를 반환한다. 환산은 위도 1도 ≈ 111,320m,
경도 1도 ≈ 111,320m × cos(위도) — 건물 한 채 크기에서는 이 근사로 충분하다.

반환 순서는 폴리곤이 자기 자신과 교차하지 않도록 시계방향으로 고정한다.

### `MapView.tsx`

기존 마커 effect들과 같은 패턴으로 effect 하나를 더한다: `map`이 준비되면 지사마다
`kakao.maps.Polygon` 하나와 라벨용 `kakao.maps.CustomOverlay` 하나를 만들고, ref에 담아
정리한다. 상수 데이터라 의존성은 `[map]` 하나뿐이다.

폴리곤은 **클릭할 수 없다**. 맛집 마커와 달리 선택 대상이 아니고, "선택한 장소" 패널에
넣을 내용도 없다. 라벨도 마찬가지로 `pointer-events: none`으로 두어 지도 조작을 막지 않는다.

줌 레벨에 따른 숨김도 하지 않는다. 지사는 5곳뿐이라 어느 배율에서든 화면을 어지럽히지 않는다.

## 검증

`rectangleCorners`가 이 변경에서 유일하게 비자명한 로직이다. `branchOffices.test.ts`에:

- 회전 0°, 폭·길이가 같은 정사각형 → 네 꼭짓점이 중심에서 등거리
- 폭 100m·길이 0m·회전 0° → 동서로만 벌어지고 위도 차이는 0에 가까움
- 회전 90° → 회전 0°의 결과를 90도 돌린 것과 같음 (폭·길이를 맞바꾼 것과 동치)
- 반환 좌표가 4개이고 모두 유한한 수

기존 vitest는 그대로 통과해야 하고, `tsc --noEmit`과 `npm run build`가 깨끗해야 한다.

수동 확인:

1. 지도에 지사 5곳이 사각형으로 보이고 각각 이름 라벨이 붙는다
2. 사각형 위를 드래그해도 지도가 정상적으로 움직인다 (폴리곤이 이벤트를 삼키지 않음)
3. 맛집 마커 클릭이 여전히 상세 컬럼을 연다
4. 각 사각형이 실제 건물과 얼마나 어긋나는지 보고, 상수 테이블의 숫자를 보정한다

## 하지 않는 것

- 건물 외곽선 API(VWorld 등) 연동 — 지사 5곳에 새 외부 의존성은 과함
- 폴리곤 클릭·호버 상호작용
- 줌 레벨별 표시/숨김
- 지사 데이터를 DB나 API로 옮기기 — 상수 5개다
